FM-03 // Engineering & logistics

Engine Room

How the game is put together in Godot 4 on your Apple Silicon Mac, where the 3D art comes from, and how we work together when I can't run the game myself.

01

The tech stack

ENGINE

Godot 4

Latest stable 4.x, the standard edition (not the .NET/C# one). Free and open source, with a native Apple Silicon build.

LANGUAGE

GDScript

Godot's own Python-like language. Easiest for you to read, no extra installs, and fast enough for this game.

RENDERER

Forward+ on Metal

Godot's highest-quality renderer: real-time shadows, global illumination (SDFGI), volumetric fog, glossy reflections.

PHYSICS

Jolt

The physics engine built into Godot 4.4+. More stable for vehicles and lots of physics debris than the default engine.

Target performance: 60 fps at 1080p on a base M1 MacBook Air with "High" settings. Higher-end M-series chips get the "Ultra" preset (more shadows, GI, fog). PROPOSED

What the real shader does

  • Glossy clear coat: that cheap injection-molded shine, with sharp highlights
  • Subsurface scattering: light glows slightly through thin parts like the helmet brim, the way real soft plastic does
  • Mold seams and flash: a faint line down the sides of each soldier, added with a texture
  • Scuffs: soldiers wear and get scratched as they take damage
  • Melt (Phase 2, flamethrower): the soldier sags, drips and darkens
One material, every model. CC0 models come in different art styles. Putting the same plastic material on all of them makes them look like they belong together, and makes them read as toys.

Why it's laid out like this

  • Swap art without touching code: art lives in assets/, behaviour lives in scripts/. Upgrading a model means replacing one file.
  • One tuning file: health, damage, speeds and AI timings are all in data/tuning.tres. You can tweak numbers in Godot's Inspector without reading any code.
  • Components: "Health" is written once and used by soldiers, vehicles and cereal boxes alike.
  • Built for growth: squads, new weapons and new levels slot into the same structure later.
06

How we work together

What I can check before you play

  • Every script carefully reviewed against the Godot 4 API
  • A game-logic simulation (damage, AI decisions) that I can test in code
  • If Godot can be downloaded here: I run the project headless to catch script errors and run automated smoke tests before every push
Right now: this cloud environment's network policy blocks the download of Godot from github.com release files. If you want me to test-run code here, you can allow that host in the environment's network settings (more on the Orders page, Q11). Without it, you are the only one who can test-run the game.

What only you can check

  • Does it feel good? Aiming, movement, vehicle handling
  • Does it look right on your screen?
  • Performance on your actual Mac. I'll add an on-screen FPS counter (F3).
  • When something breaks: Godot's red error text at the bottom of the editor. Copy and paste it to me.
